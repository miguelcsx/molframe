This is an index of the supported Python facade, not a second copy of every task guide. Start with the linked guides for examples and scientific interpretation.

## Root functions

| API | Purpose |
| --- | --- |
| `read(source, *, name=None)` | Read a path, path-like value, or bytes into a `Structure`. |

Identifier acquisition is not currently part of the Python facade. The verified boundary is local paths or caller-supplied bytes through `read()`. The Rust adapters expose a typed unavailable-provider diagnostic rather than guessing a remote URL when no authoritative identifier manifest and checksum are configured. See [Structures](/docs/structures) for the distinction between loading and acquisition.

## Structure and hierarchy

| API | Purpose |
| --- | --- |
| `Structure` | Root object: counts, hierarchy collections, coordinates, `select()`, and `edit()`. |
| `Models` / `Model` | Indexable model collection and an individual model. |
| `Chains` / `Chain` | Indexable chain collection and an individual chain with residues. |
| `Residues` / `Residue` | Indexable residue collection and an individual residue with atoms. |
| `Atoms` / `Atom` | Indexable atom collection and an atom's index, name, element, and coordinate. |

Collections support `len()` and integer indexing. Negative indexes follow Python collection conventions. See [Structures](/docs/structures).

## Selection and input objects

| API | Purpose |
| --- | --- |
| `Selection` | Atom indices, stale-selection check, model-specific coordinates, and `|`, `&`, `-` set operations. |
| `Query` | Compiled selection text with `source`, stable `fingerprint`, `select()`, and query `&`, `|`, `~` composition. |
| `QueryError` | Raised by a query that cannot run; a `ValueError` whose message quotes and underlines the query. |
| `QueryWarning` | Warned by a query that runs but is probably not what was meant; a `UserWarning`. |
| `Reader` | Read named in-memory bytes; exposes `byte_length`. |
| `StructureEditor` | Rename a chain by hierarchy index, then `finish()` a new structure. |

See [Selecting atoms](/docs/selections) and [Reading bytes and editing structures](/docs/editing-and-inputs).

Functions that take coordinates take C-contiguous `float32` arrays of shape `(n, 3)`; ones that take a structure read its own coordinates. The governed analyses (`contacts`, `hydrogen_bonds`, `salt_bridges`, `validation.clashes`, `trajectory.rmsd`) take `policy=` and return an `Analysis`.

## Array protocols

`Float32Array` and `UInt32Array` are typing protocols for coordinate and index arrays. At runtime, MolFrame returns NumPy-compatible values; users normally work with their `.shape` or pass them to NumPy-aware libraries.

<Callout type="info">
`molframe.motif.evaluate(structure, specification)` runs the declarative functional-geometry evaluation a TOML or JSON specification describes and returns one verdict per defensible mapping, with every constraint measurement kept beside it; pass `components=` for chemistry-aware atom mapping. The trajectory readers cover the self-describing formats only; formats that need caller-supplied units or topology (GSD, H5MD, AMBER ASCII) are rejected by name rather than guessed.
</Callout>
