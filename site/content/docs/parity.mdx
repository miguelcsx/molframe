# Parity ledger

Every row of the capability register starts at `β`: native code, covered by
tests, with no external differential evidence. A row moves to `✓` only when it
names a golden workflow (`GW-NNN`) whose test pins values from a named external
library at a stated version, with a stated tolerance. `crates/molframe/tests/parity_ledger.rs`
fails when a `✓` row has no GW, or when a named GW has no `gw_NNN_` test.

| Status | Meaning |
| --- | --- |
| `✓` | Native, backed by a golden workflow with pinned external evidence |
| `β` | Native, covered by tests, not yet pinned to an external reference |
| `–` | Another domain; the argument is in the Evidence column |
| `·` | The reference libraries do not have this |

## Blocked

These golden workflows cannot be promoted until their reference prerequisites are reproducible.

- **GW-031**: `complex_info` is not pinned and runnable in the reference workflow. Sources exist in the local sibling `ligare/deleteme/complex_info`; the supplied executable targets Linux x86-64.
- **GW-032**: ATPTS is not pinned and runnable in the reference workflow. Driver sources, templates and examples exist in the local sibling `ligare/deleteme/atpts`.
- **GW-044 to GW-047**: the OpenStructure, Graphein and Geomstats pins and their corpora are not selected.
